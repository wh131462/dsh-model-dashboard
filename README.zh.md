# 模型看板（model-dashboard）

**把 DeepSeek Harness 的模型配置、余额和用量收进一页。**

[![npm version](https://img.shields.io/npm/v/@eternalheart/dsh-model-dashboard.svg?label=npm)](https://www.npmjs.com/package/@eternalheart/dsh-model-dashboard)
[![license](https://img.shields.io/npm/l/@eternalheart/dsh-model-dashboard.svg)](LICENSE)
[![DeepSeek Harness](https://img.shields.io/badge/DeepSeek_Harness-0.2.x-4B6BFB)](#环境要求)

[English](README.md) | 中文

`model-dashboard` 是 DeepSeek Harness（DSH）的插件，在左侧 **自动化任务** 下方新增
**模型看板** 入口（英文界面显示为 model-dashboard）。页面分三个标签页，展示 DSH
已经掌握的模型、余额与用量：

- **概览** —— 当前在跑什么、每个供应商报告了多少余额，以及今天最值得看的
  Token 数字。
- **模型配置** —— 每个供应商路由的凭据状态、余额和模型清单；可以编辑路由、配置
  在默认浏览器中打开的官网、从网关导入模型、测试推理档位，或切换默认模型。
- **用量统计** —— Token 总量、按日图表、按模型/按供应商拆分、用量最大的会话，
  以及可选的成本估算。

它只读取 DSH 自己的服务和本 profile 的会话日志；不代理模型请求，不写会话日志，
也不上报遥测。

**设置 → 模型** 负责配置单个路由；**模型看板** 是这份配置的视图：一次看到整个
模型阵容，就地完成常用修改，并补上设置页没有的余额、用量和成本。不需要额外服务或
账户；页面跟随 DSH 界面语言，支持中文和英文。

## 环境要求

- **DeepSeek Harness 0.2.x，且带 Web 界面** —— 桌面端或 `dsh web`。本版本以
  `0.2.2-rc.3` 开发与验证；后续大版本可能需要插件更新。
- **至少配置一个模型供应商。** 可以在 **设置 → 模型** 中配置，也可以在看板内新增。
  新增自定义供应商（包括编辑它的路由）依赖官方自带的多供应商适配器；DeepSeek 官方
  路由不需要它。
- **只在从源码构建时需要 Node.js 20+。**
- **用量统计需要本 profile 的本地会话历史。** 全新 profile 的用量页一开始是空的，
  使用后才会累积。

## 安装

### 从插件页安装（推荐）

1. 打开 DSH，点击侧边栏的 **插件**。
2. 点击 **添加插件**，输入 `@eternalheart/dsh-model-dashboard`。
3. 点击 **安装**。如果对话框要求选择 registry，保留 npm，或选择适合当前网络的镜像。
4. 保持这个插件包处于开启状态。侧边栏 **自动化任务** 下方会出现 **模型看板**。
5. 打开它。如果入口暂时没出现，刷新页面或重启 DSH。

npm 包名是 `@eternalheart/dsh-model-dashboard`；插件页会从你选择的 registry
安装最新版本。

### 从命令行安装

适用于你自己启动的 profile，例如 `web`：

```sh
dsh plugin --profile <profile> add @eternalheart/dsh-model-dashboard
```

`dsh plugin` 会在该 profile 目录里调用 pnpm，把包添加为依赖，并把插件包追加到
profile 的 `bundles` 列表。它需要 `PATH` 上有 pnpm（或配置了 `pnpmCommand`）。
重启该 profile，或等待 HMR 重新加载。桌面端请使用 **插件** 页：`desktop` profile
由桌面应用管理，npm CLI 会拒绝它的插件管理请求。

### 从本地源码安装

```sh
git clone https://github.com/wh131462/dsh-model-dashboard.git
cd dsh-model-dashboard
npm install
npm run build
```

然后在 DSH 中打开 **插件 → 添加插件**，粘贴检出的绝对路径（或从添加菜单选择
第三方插件安装项）。以链接方式安装的目录是实时的：修改 `src/` 后重新执行
`npm run build`，并重启 DSH。

### 停用或卸载

- 在 **插件** 页把 `model-dashboard` 插件包 **关闭**，即可隐藏侧边栏入口而不卸载；
  重新开启即可恢复。
- 在 **插件** 页 **卸载**，或执行：

  ```sh
  dsh plugin --profile <profile> remove @eternalheart/dsh-model-dashboard
  ```

- 用量缓存是派生数据，位于 `$DSH_HOME/cache/model-dashboard/`（默认
  `~/.dsh/cache/model-dashboard/`）。可以删除以释放空间；下次扫描会重新生成。

## 快速开始

1. **打开看板。** 首次加载可能启动用量扫描；页头会显示「扫描中 x/y」，直到扫描
   完成。历史很大时需要几分钟，扫描在后台进行。
2. **看概览。** 打开时显示当前默认模型；如果还没有默认模型，点击 **切换默认** 会跳到
   模型配置。
3. **选默认模型。** 在 **模型配置** 中展开一个活动路由，在任意模型上点
   **设为默认**。选择会保存下来，供后续会话使用。
4. **查余额。** 页面加载时会查询并缓存余额；**刷新余额** / **全部刷新余额** 会强制
   重新探测。
5. **配价格（可选）。** 只有 `pricing` 中配置了价格的模型才会显示成本；见
   [成本估算](#成本估算)。

## 概览

**概览** 回答两个问题：现在跑的是什么，还剩多少钱。

- **页头** —— 官方账户余额、用量扫描状态、最近刷新时间，以及 **刷新**。页面还没
  查过余额时，**刷新** 会顺带查询一次。
- **默认模型** —— 用大号字显示模型名，附供应商与推理档位标签、接入地址、
  **复制模型 ID** 和 **切换默认**。
- **指标** —— 今日 Token（本地日历日）、近 7 日 Token（含今日）、累计请求数、
  缓存命中率。
- **官方账户余额** —— 登录后显示平台钱包与赠送余额；未登录但官方 API Key 路由
  探测到余额时，显示该余额并注明来源。
- **供应商余额** —— 每个供应商一行，带密钥状态点和最近一次余额；
  **全部刷新余额** 重新探测。
- **页脚** —— 用量缓存的构建时间、配置价格后的近 7 日估算成本、当前扫描状态。

## 模型配置

**模型配置** 是当前模型配置的结构视图，覆盖 DeepSeek 官方路由，以及多供应商
适配器暴露的任何路由——OpenAI 兼容、Anthropic、Google 协议都可以查看。

- 每个 **供应商行** 显示密钥状态点、显示名称与路由 ID、模型数量和当前余额；
  默认供应商带品牌色标记。
- **展开** 一行可看到分栏的事实信息——接入地址（可复制）、协议、路由状态、凭据
  状态与来源、供应商 **官网**——以及提示（休眠 / 缺少密钥 / 模型列表不可用）和
  模型清单（上下文窗口、推理档位、按档位测试）。
- **官网** —— 通过 **添加官网** / **编辑官网** 保存该供应商的完整 http(s) 地址；点击
  链接会用默认浏览器打开（`dsh web` 下为新标签页）。官网是看板的附加注解，不写入
  适配器配置，保存在 `$DSH_HOME/model-dashboard/provider-sites.json`。
- 在模型上点击 **测试档位** 可探测上游；点击 **设为默认** 通过 DSH 的默认模型服务保存
  选择。
- 行内的 **刷新余额** 只探测该供应商；工具栏的 **刷新余额** 探测全部供应商。
- **新增供应商** 声明新路由；**展开全部 / 收起全部** 用于长列表。

适配器路由没有活动实例的供应商标记为 **休眠**：显示 profile 中声明的模型（如果
有），不能设为默认。没有密钥的供应商显示红点和 **缺少密钥**；模型仍可查看，但
余额探测和网关发现可能失败。

### 可以编辑什么

编辑器与 **设置 → 模型** 使用同一份配置 revision 和同一个凭据库；校验规则相同，
表单打开期间配置被别处改过时会拒绝保存，而不是覆盖新值。

| 路由 | 可编辑 |
|---|---|
| 多供应商适配器声明的路由 | 显示名称、协议、接入地址、凭据引用、API Key、声明的模型清单。组合自带的继承路由可以覆盖，但不能删除；你自己 profile 声明的路由可以删除。 |
| DeepSeek 官方 API Key 路由 | 接入地址、凭据引用、API Key、声明的模型 |
| DeepSeek 官方账户路由 | 只读；它的设置属于账户登录 |

模型字段：ID、显示名称、上下文窗口、最大输出、输入模态（文本、图片）、推理档位。
模型清单留空表示继续继承适配器目录，编辑器会明确说明，而不是悄悄复制一份。

**API Key 与路由配置分离。** 点击 **保存密钥** 会把密钥写入 DSH 凭据库，键是该路由的
凭据引用。密钥不会写进 profile patch，不会回传给页面，只显示凭据库的掩码预览。
**清除密钥** 需要二次确认。凭据引用是环境变量风格的名字：密钥可以来自环境变量，
也可以来自凭据库，展开行会注明来源。必须先保存凭据引用，才能保存密钥；编辑器在
引用缺失时会提示。

**冲突：** 如果表单打开期间配置被修改，保存会报冲突并提供 **重新读取**。请重新读取
后再保存，不要用旧值覆盖新值。

### 新增供应商

1. 点击 **新增供应商**。
2. 填写 **供应商 ID**（小写字母、数字和连字符，必须以字母或数字开头）和
   **接入地址**。
3. 可选填写显示名称、凭据引用和 API Key。
4. 点击 **连接并读取模型**。不手动选择协议时，会自动识别；填写了 API Key 会先写入
   凭据库，再用于读取模型。
5. 选择要声明的模型，点击 **创建**。模型会随新路由一起写入。

新路由会立即写入；写入后页面会重新读取发现结果。

### 从网关读取模型

在路由编辑器里点击 **从网关读取模型**：先向接入地址索取模型目录（没有写协议时自动
识别），然后可以搜索、全选、反选并批量导入。已声明的模型保留原有推理档位，导入只
刷新名称和上下文窗口。新增表单里的 **连接并读取模型** 使用同一个选择器。

### 推理档位

两个问题看起来一样，其实不同：

1. **DSH 会提供哪些档位。** 由适配器按路由和模型声明。DeepSeek 路由固定为
   Off / Low / High / Max；没有声明的模型一个档位都不提供，输入框旁不会出现推理
   强度控件。
2. **端点实际接受哪些档位。** 声明了也可能被网关拒绝，或者被接受但静默忽略。

**用 chips 编辑档位。** 在模型编辑器里把档位做成开关，每个选中的档位旁显示线上
拼写；`Off` 可以留空，表示「不发送该字段」。网关对某个档位的叫法不同时，用
**自定义线上拼写** 逐个填写。

**测试档位** 回答第二个问题。对适配器提供的每个档位，先做一次免费的适配器能力
检查，再发一次极小的真实请求（`maxTokens: 24`、提示词 `ping`、20 秒超时），然后
报告：

- `✓ 接受`
- `— 未提供`（这是配置事实，不是网络结果）
- `✕ 拒绝`（带网关返回的代码与消息）
- `? 无法判定`（没有在时限内收到结论）

每个档位会消耗少量 Token，探测按顺序执行。不要把端点会拒绝的档位声明上去：输入框
会提供一个必定失败的选项。

**探测** 反过来：在编辑器里对已保存的模型发送候选原始值（省略、`none`、`minimal`
… `max`），显示带推理 Token 数的接受矩阵，并给出建议映射；**应用建议** 会填入
模型的推理档位 chips，保存表单后生效。探测目前只支持 `openai-completions` 协议；
其他协议请用「测试档位」并手动编辑 chips。

「接受」不等于「生效」：有的网关收下取值却不理会，需要在档位之间对比推理 Token 数
或思考内容。

## 用量统计

**用量统计** 汇总本 profile 会话日志里的 Token 账目：每条助手消息的持久化用量记录、
产生它的路由，以及事件时间。

- **时间范围** —— 今日、近 7 日、近 30 日、全部；默认近 7 日。全部范围的总量覆盖
  所有会话，图表最多显示最近 30 天。
- **头部** —— 总 Token、请求数、扫描覆盖率。
- **指标** —— 输入、输出、缓存读取、缓存写入、缓存命中率、估算成本。
- **每日图表** —— 按本地日历日的 Token 用量。
- **拆分表** —— 按模型和按供应商，含占比、各 Token 口径、请求数和成本。
- **会话** —— 所选范围内用量最大的会话（界面标题为「最近会话」），带 Token 合计和
  请求数。

计数规则：

- **请求数** 统计带 Token 账目的助手消息。
- **推理 Token** 不加入任何合计。
- **输入**、**缓存读取**、**缓存写入** 是互不重叠的提示词口径；提示词为三者之和，
  总 Token 再加 **输出**。缓存命中率为
  `cacheRead / (input + cacheRead + cacheWrite)`。
- 时间范围按本机时区、以天为粒度。

历史很大时，首轮扫描在后台运行；页头显示「扫描中 x/y」，页面会持续轮询直到
稳定。之后的扫描只读取 revision 变化过的会话的新增尾部。**重新扫描** 会丢弃缓存并
全量重算。

缓存位于 `$DSH_HOME/cache/model-dashboard/usage-cache.json`（目录可用 `cacheDir`
修改）。用量只覆盖本 profile 会话后端保存的会话；其他 profile 或其他机器不包含在内。

### 成本估算

成本是估算值，不是账单。在插件的 `pricing` 里按每百万 Token 配置价格：

```yaml
pricing:
  deepseek-official/deepseek-flash: { input: 2, output: 8, cacheRead: 0.2 }
  gpt-6.1-sol: { input: 10, output: 30 }
```

- 键是 `provider/model`，或只写模型 ID（对所有供应商生效）；完全匹配的
  `provider/model` 优先。
- 省略 `cacheRead` / `cacheWrite` 时默认取 `input`。
- 未配置价格的模型成本显示 `—`；合计只累加已配置价格的模型，所以只配一部分时给出
  的是部分成本，而不是编造的数字。
- 货币标签取自 `currency`（默认 `CNY`，也常用 `USD`）。供应商余额保留各自返回的
  货币。

## 余额

DeepSeek 官方两条路由各覆盖一层：

- **账户路由** 通过已保存的账户登录显示平台钱包。
- **API Key 路由** 用该路由已配置的凭据探测
  `https://api.deepseek.com/user/balance`。平台账号未登录、但探测成功时，概览会
  显示 API Key 的余额并注明来源。

其他供应商按需探测，结果缓存 `balanceCacheSeconds` 秒：

1. `GET …/user/balance` —— DeepSeek 的返回结构
   （`balance_infos[].total_balance`）。接入地址的 host 含 `deepseek` 时优先尝试。
2. `GET …/dashboard/billing/subscription` 与
   `GET …/dashboard/billing/usage?start_date=…&end_date=…` —— OpenAI 计费兼容接口，
   one-api / new-api 之类的中继会提供。余额为
   `hard_limit_usd - total_usage / 100`，以美元计。

两种结构都会在配置的 base URL 与同一 origin 下尝试：中继常把 API 放在 `/v1` 下，
而计费接口在根路径。两种结构都不提供的网关显示 **不可用**；鉴权失败或超时显示
**读取失败**。one-api / new-api 对没有有限额度的账号返回哨兵值（100,000,000
「美元」），这种情况显示为 **无限额度** 加已用金额，而不是九位数余额。

### 自定义余额探测

自带接口的中继可以在 `providerBalance` 中按路由 ID 描述：

```yaml
providerBalance:
  acme-relay:
    mode: custom              # auto | openai-billing | deepseek | custom | off
    url: https://relay.example/api/me
    amountPath: data.balance  # 指向 JSON 回复的点路径
    limitPath: data.quota
    usedPath: data.used
    scale: 0.000002           # 字段乘以该系数，例如把额度单位换算成美元
    currency: USD
    headers:
      x-tenant: acme
```

`mode` 默认是 `auto`。`auto`、`openai-billing`、`deepseek` 决定先试哪种内置结构
（`auto` 按端点 host 判断），`custom` 使用 `url`，`off` 关闭该路由的探测。同一
对象里的 `baseURL` 会覆盖内置探测使用的地址。`amountPath`、`limitPath`、
`usedPath` 是点路径，`scale` 会乘以读到的数值，`headers` 追加请求头。

探测只把该供应商自己的凭据发到该供应商自己的余额接口；页面永远拿不到密钥，只有
金额和状态会回传。

## 配置项

所有配置都是可选的。默认值由插件包提供；在 profile 自己的 patch 文件里覆盖：

`$DSH_HOME/profiles/<profile>/cordis.patch.yml`
（默认 `~/.dsh/profiles/<profile>/cordis.patch.yml`；桌面端 profile 是 `desktop`，
`dsh web` 使用 `web`）。

```yaml
- id: model-dashboard
  config:
    currency: CNY
    balanceCacheSeconds: 300
    pricing:
      deepseek-official/deepseek-flash: { input: 2, output: 8, cacheRead: 0.2 }
    providerBalance:
      acme-relay:
        mode: custom
        url: https://relay.example/api/me
        amountPath: data.balance
```

按行覆盖会替换整个 `config`，不是深度合并。要保留的非默认项必须一起写上；没写的
键回落到下表默认值。

| 字段 | 默认值 | 含义 |
|---|---|---|
| `locale` | `auto` | Host 提供文本的语言（模型徽标、账户元数据）；页面跟随 DSH 界面语言 |
| `currency` | `CNY` | 成本估算的货币标签 |
| `scanConcurrency` | `3` | 扫描时并行读取的会话日志数 |
| `maxSessions` | `0` | 每轮扫描最新的 N 个待扫描会话；`0` 表示全部 |
| `cacheDir` | `''` | 用量缓存目录；留空使用 `$DSH_HOME/cache/model-dashboard` |
| `dataDir` | `''` | 供应商官网数据目录；留空使用 `$DSH_HOME/model-dashboard` |
| `balanceTimeoutMs` | `8000` | 单次余额 HTTP 请求的超时 |
| `balanceCacheSeconds` | `300` | 探测结果复用时长（最少 5 秒） |
| `pricing` | `{}` | 成本表，单位为每 1,000,000 Token |
| `providerBalance` | `{}` | 按供应商的探测覆盖项 |

启用 HMR 时，DSH 会在 profile patch 变化后重新加载；没有 HMR 时重启 profile。
插件在激活时读取这份配置。

## 隐私与数据

- **读取：** 供应商路由、模型元数据、设置投影、凭据的 **状态**（是否配置、来源、
  掩码预览）、官方账户余额、本 profile 的会话日志。
- **写入：** 只有在你保存密钥时写凭据库，在你保存供应商时写设置，在你点击
  **设为默认** 时写默认模型选择，在你保存官网时写
  `$DSH_HOME/model-dashboard/`，以及写 `$DSH_HOME/cache/model-dashboard/` 下的
  用量缓存。插件不写你的会话日志。
- **网络：** 余额探测发往每个供应商自己的端点，使用该供应商自己的凭据，并按
  `balanceCacheSeconds` 缓存。点击 **从网关读取模型** 会请求网关的模型目录；
  **测试档位** 和 **探测** 会发极小的真实请求。页面本身不会发送聊天补全请求。
- **不上报遥测**；除余额探测和你主动触发的网关请求外，数据不离开本机。
- 页面的 JSON 通道只接受所有者连接；密钥不会出现在响应里。

## 常见问题

| 现象 | 检查 |
|---|---|
| 侧边栏没有 **模型看板** 入口 | 插件包已在 **插件** 页安装并开启；当前是 Web 界面（不是 TUI）；刷新或重启 DSH。 |
| 提示「还没有配置模型供应商」 | 在 **设置 → 模型** 中配置路由，或在 **模型配置 → 新增供应商** 中新增。 |
| 余额显示 **不可用** | 网关不提供两种计费结构、路由没有密钥，或 DeepSeek 账户未登录。中继有自己的余额接口时，配 [自定义余额探测](#自定义余额探测)。 |
| 余额显示 **读取失败** | 通常是密钥 401/403，或超时/代理问题。展开供应商查看凭据来源后重试。 |
| 用量为空或扫描一直不结束 | 新 profile 没有会话日志；历史大时需要时间。看「扫描中 x/y」的进度，必要时点击 **重新扫描**；确认缓存目录可写。 |
| 成本显示 `—` | 该模型没配价格。在 `pricing` 中添加；合计只统计已配置价格的模型。 |
| 保存提示冲突 | 配置在另一个标签页或 **设置 → 模型** 中被修改。在编辑器里点击 **重新读取** 后再保存。 |
| 无法编辑某个路由 | 官方账户路由只读；组合继承的路由可以覆盖但不能删除；未注册/休眠路由不能设为默认。 |
| 无法新增供应商 | 当前组合没有挂载多供应商适配器。在 DSH 中启用它，或改用 **设置 → 模型**。 |
| 所有推理档位都被拒绝 | 网关不接受声明的线上值。OpenAI 兼容路由可用 **探测**，否则减少档位；不要把端点会拒绝的档位声明上去。 |
| DSH 升级后页面空白或插件激活失败 | 本版本面向 DSH 0.2.x；请安装更新后的插件或使用兼容的 DSH，并检查 Host 日志里的激活错误。 |
| 数字与其他工具不一致 | 用量只覆盖本 profile，按本机时区按天分桶；成本按你的 `pricing` 推导，不是供应商账单。 |

## 开发

```sh
npm install
npm run build   # src/host -> index.js，src/client -> client.js
npm test        # Host 测试套件
```

- `src/host/` —— 发现、余额、用量汇总、编辑，以及带鉴权的 JSON 通道。
- `src/client/` —— 侧边栏入口与三个标签页。
- `build.mjs` —— 用 esbuild 打包 Host（ESM）与 Client（CJS，按 DSH 模块加载器包装）。
- `cordis.patch.yml` —— 插件包插入的那一行及其默认配置。

构建产物 `index.js` 与 `client.js` 会提交到仓库，所以本地目录安装不需要先构建。修改
`src/` 后重新构建，并重启 DSH。

发布：`npm run pub` 负责版本号、构建、测试与发布，目标是官方源
`registry.npmjs.org`；推送 `feat: vX.Y.Z` 提交后，GitHub Actions 会创建对应的
Release。首次发布需先执行 `npm login --registry=https://registry.npmjs.org`；账号开启
2FA 时 npm 会打开浏览器要求确认，按提示完成即可。

问题和 Bug 欢迎提交到
[GitHub Issues](https://github.com/wh131462/dsh-model-dashboard/issues)；也欢迎 PR。
